# StudyFlow UI/UX改修仕様書

更新日: 2026-10-07 · 対象ブランチ: `redesign/responsive-ui`

## 1. 改修の目的

Instagram・Xのように、現在地、主要操作、次の行動がすぐに分かる学習アプリにする。PC・iPad・スマホで、それぞれの表示幅と入力方法に合った操作を提供する。SNSのブランドを複製せず、StudyFlowのインディゴ、学習記録、仲間との交流を中心に設計する。

この仕様を先にコミットし、共通UI、ホーム、主要画面、検証の順で実装する。GitHubの書き込みはユーザー指定のe2510025アカウントで行う。

## 2. 確認した現状

- Next.js 16.1.6 App Router、React 19、Tailwind CSS 4、Zustand、Framer Motion、Recharts。
- Vercelでデプロイ済み。`vercel.json`はNext.js、`prisma generate && next build`、`hnd1`を指定。
- DBの主経路はFirebase Firestore。クライアントの`src/lib/firestore/*`とサーバーのFirestore Lite経由で読み書きする。
- ログインはNextAuthのJWTセッション。メール・パスワードはFirestore `users`とbcryptを使用し、環境設定があればGoogleログインも提供する。Firebase Authへの置き換えは行わない。
- 暗記APIもFirestoreを使用する。PrismaスキーマとMongoDB移行用コードは存在するが、今回のDB移行は対象外。
- READMEにCloudflare・MongoDBの記述があるが、今回の運用前提はユーザーが指定したVercel・Firebase。
- 現行UIは固定配置された複数の上部ボタン、10項目以上のメニュー、タイマー画面のホバー依存ナビゲーション、固定高さのダッシュボードが使いにくさの原因。
- 白・グレー・ダーク・カスタムの既存テーマと集中モードを維持する。

## 4. ナビゲーションと共通レイアウト

主要ナビゲーションは「ホーム・タイマー・タイムライン・暗記・その他」の5つ。その他を開くと学習、交流、アカウントのグループに分けて全機能へ到達できる。URLは維持し、深い画面でも親ナビを選択状態にする。

| 表示幅・端末 | レイアウトと操作 |
| --- | --- |
| 767px以下・スマホ／狭いSplit View | 上部にブランドまたは現在地、DM、通知、アカウント。下部にラベル付きの5項目ナビ。その他はダイアログとして開く |
| 768〜1199px・iPad／小さいPC | 80pxのサイドレール。アイコンと短いラベルを表示し、ヘッダーはレールの右へ。その他は同じダイアログを利用 |
| 1200px以上・PC／広いiPad横向き | 240pxのラベル付きサイドバー。主要ナビと補助グループを表示。本文は最大1280px、フィードは最大680px |

ヘッダーをひとつの領域にまとめ、上部ボタンとページタイトルが重ならないようにする。本文には固定ナビとセーフエリア分の余白を設ける。集中モードでは既存と同じく共通UIを隠し、タイマー側の終了操作を維持する。

その他ダイアログは開いた操作へフォーカスを戻し、Escape・背景・閉じるボタンで閉じる。開いている間は背景スクロールを止め、Tab操作をダイアログ内に保つ。モバイル以外でもキーボードで全機能に到達可能とする。

## 5. ビジュアル仕様

- インディゴを主アクセントに使用し、白・グレー・ダーク・カスタムの既存テーマに対応する。淡い背景と落ち着いた境界線で情報を区切る。
- 本文16px、補足14pxを基本とする。本文の行高は1.6、見出しは24〜32px。日本語向けのシステムフォントをフォールバックに加える。
- 余白は4・8・12・16・24・32・48px、角丸は12〜20pxを基本とする。カードの過剰な影、ホバーによる拡大、常時点滅は抑える。
- 主ボタンはアクセント背景と十分なコントラストを持つ文字。カスタムテーマの白アクセントでは濃い文字を使う。
- 通常本文・補足はコントラスト4.5:1以上を目標とする。ユーザーが自由に指定した背景でも本文パネルのコントラストを確保する。
- 主要操作、ナビ、アイコンボタンの操作領域は44×44px以上。アイコンだけのボタンに日本語のアクセシブルな名前を付ける。
- キーボードフォーカスを明示し、先頭に本文へのスキップリンクを提供する。動きを減らす設定を尊重する。

## 6. 画面別仕様

### 6.1 ホーム `/`

目的は「今日の進捗を知り、すぐ学習を始める」。ページタイトル、短い説明、主操作「学習を始める／タイマーに戻る」、統計の順で配置する。実行中・一時停止中のタイマーはホームから状態と再開先を確認できる。

統計は今日の時間、今週の合計、連続学習、ポイントを維持。スマホは2列、十分な幅では4列。学習推移と教科内訳はスマホで縦並び、広い画面で2列。ヒートマップと最近の記録、共有カードは内容の高さに合わせて並べる。ヒートマップの個別日情報はタッチとキーボードでも確認できるようにする。

空状態には記録がない理由と学習を始める導線を置く。既存Zustandへ反映されるFirestoreの記録を使用し、新しい購読を追加しない。週・月・年・全期間の切替と共有画像の保存を維持する。

### 6.2 タイマー `/timer`

目的は「教科を選んで計測し、記録を保存する」。計測ロジック、バックグラウンド補正、集中ボーナス、保存処理は維持する。教科とモード、時間表示、開始／一時停止／終了を明確にする。設定、ToDo、プリセットなどの補助操作は主操作を押し下げないように整理する。

PC・iPad・スマホに共通ナビを提供し、ホバー依存を除去する。既存の集中モードの開始・終了は維持。記録終了時のメモ入力、二重保存防止、教科ID、duration、points、自動投稿の設定を保持する。

### 6.3 タイムライン `/timeline`

目的は「仲間の学習を読む・反応する・投稿する」。最大680pxの読みやすいフィード幅。画面冒頭の投稿入口、整列した投稿者・時間・本文・画像・リアクションを提供する。

投稿は区切り線で並べ、過剰なカードの入れ子を抑える。詳細ページへの導線はキーボードにも提供する。画像投稿、メンション候補、返信、引用、編集、削除、通報、共有の処理とデータ形式は保持する。投稿フォームの入力、送信中、失敗、キャンセルを確認する。

### 6.4 暗記 `/memorize`

目的は「デッキを見つけて復習・テストに進む」。タイトルと作成操作を統一し、デッキ一覧、問題一覧、復習への入口を分かりやすくする。既存のAPIとデータを利用し、デッキ・カード・問題のURLとIDを保持する。読み込み失敗を空の一覧として表示しない。

### 6.5 補助画面と共通状態

教科・会話・ランキング・設定・管理画面などは既存の内容と処理を維持し、共通ナビとテーマを適用する。各画面専用の全面的な再設計は、主要画面のレビュー後に仕様を追加できる。

読み込みと空状態を区別する。フォームは項目名、入力値、エラーを維持し、保存失敗時に入力を消さない。通知パネルは画面幅を超えず、閉じる操作を提供する。ダイアログと固定UIが仮想キーボードやナビに隠れないようにする。

## 7. Vercel・Firebaseの運用条件

既存のFirebase接続設定、Firestoreパス・ID・フィールド・セキュリティルール・インデックスを保持する。Firestore→MongoDBの移行スクリプトは実行しない。NextAuthのセッションCookie、UID変換、onboarding、権限制御を変更しない。

GitHub書き込みはe2510025の接続を利用し、改修ブランチへ段階的に反映する。`main`へ直接プッシュせず、検証した差分をPRで確認できる形にする。Vercelの既存ビルド設定を維持し、本番公開・DB移行は今回実行しない。

接続済みVercelの一覧には`studyflow`があるが、対象チームの詳細取得は403、ローカルCLIでも対象スコープへアクセスできなかった。本番ブランチと環境変数の詳細は未確認。Previewが本番Firebaseに接続する可能性があるため、Previewの書き込み検証も環境確認後に実施する。

## 8. 実装とコミット順序

1. この仕様書をコミットしてGitHubの改修ブランチへ反映する。
2. 共通ナビ、ヘッダー、その他ダイアログ、テーマを実装し、静的検証後にコミット・反映する。
3. ホームと主要画面を改修し、不要なUI処理を除去する。まとまった画面単位でコミット・反映する。
4. ビルド、型、変更ファイルのlint、画面幅と操作を検証し、結果と残課題を記録する。PRを作成する。

## 9. 受け入れ条件

- 幅360・390・430・768・820・1024・1180・1280・1440pxでページ全体に横スクロールが発生しない。
- iPadの縦・横・Split View相当の幅でナビと主要操作をタッチできる。実機とブラウザエミュレーションの検証範囲は区別して報告する。
- 既存ルートの直接アクセスを維持する。終了対象の実績・掲示板には案内を表示する。親ナビの選択表示、戻るを維持する。
- その他ダイアログの開閉、Escape、フォーカス、背景スクロール、アカウント・通知パネルを確認する。
- ホームの空状態、記録あり、長い名前、実行中タイマー、4テーマ、グラフの期間切替を確認する。
- タイマー、投稿、暗記の既存処理への接続をコードと利用可能な検証環境で確認する。
- `npm run build`、型検査、変更したファイルのlintを実行する。既存のlint問題と新しい問題を区別する。
- 本番Firebaseの書き込み検証や実機確認ができない場合は、未確認事項として明記する。
